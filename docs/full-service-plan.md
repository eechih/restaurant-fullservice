# 全服務餐廳 PoC 計畫

- **目標：** 中大型全服務餐廳的 POS + KDS，內外場分工明確
- **起點：** 複製自 `restaurant-pos-kds`（commit `906f478`），沿用 Amplify Gen 2 + React、TanStack Router/Query、Repository 架構
- **建立日期：** 2026-11-06

## 和原 PoC 的差別

原 PoC 為小吃店設計：每一輪都先付款才送廚，帳號只分店長和員工。全服務餐廳的做法不同：

| | 原 PoC | 全服務餐廳 |
|---|---|---|
| 付款 | 每輪先付款才送廚 | **先吃後付**，離開前統一結帳，可拆帳 |
| 點餐的人 | 顧客掃碼或櫃台 | 主要是服務員，顧客掃碼為輔 |
| 角色 | 店長、員工 | 店長、主管、櫃台、服務員、廚房 |
| 廚房 | 一個 KDS 看全部 | 依出餐站分線，出菜口統整 |
| 桌況 | 空桌、用餐中 | 空桌、用餐中、**待清理**，加上候位 |

## 系統藍圖

業界成熟的餐廳系統分為前廳、後廚、後台三塊。這個 PoC 依序補齊：

| 系統 | 內容 | 階段 |
|---|---|---|
| POS | 點餐、桌位圖、先吃後付、拆帳結帳 | 1 |
| 角色與權限 | 依職務分權，取消要主管核准 | 1 |
| KDS | 依出餐站分線、出菜口、計時與超時警示 | 1 |
| 桌況與候位 | 待清理狀態、候位名單、帶位 | 1 |
| 發票與收據 | 電子發票、載具、統編、收據列印 | 2，正式營業前必做 |
| 服務費與折扣 | 一成服務費、折扣需主管核准 | 2 |
| 訂位 | 線上與電話訂位，和候位整合 | 2 |
| 出餐分析 | 記錄每道菜的製作時間，找出瓶頸 | 2 |
| 庫存 | 依食材用量（BOM）扣庫、安全庫存提醒、採購建議 | 3 |
| 排班與打卡（WFM） | 打卡、排班、勞基法檢查、營業額對工時 | 4 |
| 會員（CRM） | 用餐偏好、行銷推播 | 5 |
| 外送整合 | Uber Eats、Foodpanda 訂單進 POS | 5，需先和平台簽約 |

## 第一階段的設計

以下三點已於 2026-11-06 確認：顧客掃碼點的單要服務員確認後才送廚、取消已送廚的品項要主管核准、KDS 依出餐站拆單並設出菜口。

### 1. 先吃後付、桌邊結帳

- **送廚不必付款：** 服務員點的單直接送廚，每輪成為一張工作單，全部掛在這桌的帳單上。
- **顧客掃碼點餐：** 掃碼點的單先進「待確認」，服務員確認後才送廚。這樣可以防止惡作劇，也能擋下上一組客人留著的連結：直接送廚的話，舊連結點的菜會算到下一組客人的帳上。
- **結帳：** 客人要結帳時，服務員或櫃台開啟帳單，可以：
  - 整桌一次付清；
  - **依品項拆帳**：每個人勾自己點的；
  - **平均分攤**：分成 N 份。
  - 一張帳單可以有多筆付款，例如一部分現金、一部分刷卡。付清後桌子變成「待清理」。
- **帳單計算由後端負責：** 金額、拆帳、付款都在 Lambda 驗算，前端算的只是預估。
- **取消品項：** 結帳前取消，不需退款。已送廚的品項要主管核准，見下一節。

### 2. 角色與權限

一個帳號可以同時有多個角色（Cognito 群組）。

| 角色 | 可以做的事 |
|---|---|
| 店長 | 全部，包括菜單、桌位、帳號、報表 |
| 主管 | 現場調度、核准取消和折扣、看當日報表 |
| 櫃台 | 帶位、候位、結帳收款 |
| 服務員 | 開桌、點餐、確認顧客掃碼的單、上菜、請求結帳 |
| 廚房 | 只看 KDS，改製作狀態 |

- **主管核准：** 服務員取消已送廚的品項時，會送出一筆「取消申請」，主管在自己的裝置上核准或駁回。核准前，廚房畫面就會標示「申請取消中」。
- **畫面依角色調整：** 例如廚房帳號登入後只會看到 KDS。

### 3. KDS 分線

- **出餐站：** 店長設定出餐站，例如炒台、烤台、砧板、冷盤、飲料吧。每個分類指定一個預設站，個別品項可以另外指定。
- **依站拆單：** 送廚時，一輪點單會依品項拆成各站的工作單，每張有自己的狀態，各站只看自己的單。
- **出菜口（Expo）：** 另一個畫面依桌、依輪次彙整各站進度，全部完成才通知服務員上菜，避免同一桌的菜分批送出。

### 4. 桌況與帶位

- **桌況：** 空桌 → 用餐中 → 已結帳**待清理** → 撤桌人員按「已清理」→ 空桌。
- **候位名單：** 櫃台登記稱呼、人數、電話（選填），系統依人數提示適合的空桌。帶位時直接開桌。
- **桌位分區：** 桌位可以分區，例如一樓、二樓、包廂。之後可以把分區指派給服務員。

## 待決定

- **服務費：** 第一階段先不收，第二階段加入可設定的服務費。
- **QR Code 輪換：** 掃碼點的單要服務員確認，所以第一階段先不做每組客人換一次 QR Code。
- **離線：** 和原 PoC 一樣，斷線時不能送廚和結帳。
